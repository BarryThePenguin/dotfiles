# Issue tracker

Issues and PRDs for this repo live in the issue tracker. **All operations route through the Pi extension tools**. The extension is tracker-agnostic: the same tool surface speaks to whichever tracker the working directory selects.

## Generic issue operations

The extension exposes a single tool surface for every kind of issue — specs, triage, wayfinder maps, and decision tickets.

- **Create an issue**: `issue_create({ title, body?, labels? })` → `{ id, url }`. `to-spec` and `to-tickets` apply the `ready-for-agent` label at creation.
- **Read an issue**: `issue_read({ id })` → the full `Issue` — `{ id, url, title, body, labels, status: "open"|"closed", comments: [{ content, postedAt? }], createdAt?, updatedAt? }`. Accepts an id or URL.
- **List issues**: `issue_list({ state?: "open"|"closed"|"any" (default "open"), labels?: string[] (all-of), unlabeled?: boolean })` → `Issue[]` oldest first.
- **Comment on an issue**: `issue_comment({ id, body })` → `{ comment: { content, postedAt? } }`. Every triage comment must start with `> *This was generated by AI during triage.*`.
- **Apply / remove labels**: `issue_label({ id, add?, remove? })` → `{ labels }` — delta semantics (final = current ∪ add − remove), never a blind replace.
- **Close an issue**: `issue_close({ id, comment? })` → `{ status: "closed" }`.
- **Status**: every read/list returns the issue's `status`.

**By-reference resolution.** Issue references are **task ids or URLs**. Bare `#42` / `!67` references in commit messages or conversation do not resolve through the tools — look the referenced issue up by the id/URL written in the reference.

## Triage labels

The five state roles are recorded with the canonical strings — `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix` — see `docs/agents/triage-labels.md`. `bug`/`enhancement` are classification vocabulary, never labels.

## When a skill says "publish to the issue tracker"

Create an issue with `issue_create` — or `wayfinder_chart` / `wayfinder_create_ticket` for wayfinder resources.

## When a skill says "fetch the relevant ticket"

`issue_read` with the issue's id or URL — or `wayfinder_get_map` / `wayfinder_get_ticket` for wayfinder resources.

## Wayfinding operations

Used by `/wayfinder`. The **map** is an issue carrying the `wayfinder_map` label; **tickets** are its children, each carrying a `wayfinder_<type>` label (`research`/`prototype`/`grilling`/`task`).

- **Map**: `wayfinder_chart` — creates the map (destination, notes, decisions-so-far, fog).
- **Child ticket**: `wayfinder_create_ticket` — creates a child issue of the map carrying its type label.
- **Blocking**: `wayfinder_set_blocking` — where the tracker has no native dependencies, blocking is recorded as a `Blocked by:` section in the ticket body. A ticket is unblocked when every listed blocker is closed.
- **Frontier**: `wayfinder_list_frontier` — the map's open, unblocked, unclaimed children.
- **Claim**: `wayfinder_claim` — recorded as a `Claimed by:` header in the ticket body; an open, unassigned ticket is unclaimed.
- **Resolve**: `wayfinder_resolve` — posts the resolution comment, closes the ticket, and appends the decision gist to the map's Decisions-so-far.
- **Read / update**: `wayfinder_get_map`, `wayfinder_get_ticket`, `wayfinder_list_maps`, `wayfinder_update_map` (replaces one map section).
