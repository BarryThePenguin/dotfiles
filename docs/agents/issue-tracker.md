# Issue tracker

The issue tracker is where this repo's Issues and Specs live. The engineering
skills use the tracker through the Pi issue-tools extension and do not need to
know which backend is selected.

## Conventions

Use the Pi tools for all tracker operations:

- **Create an Issue**: `issue_create({ title, body?, labels? })` → `{ id, url }`.
- **Read an Issue**: `issue_read({ id })` → body, labels, status, comments, and timestamps.
- **List Issues**: `issue_list({ state?, labels?, unlabeled? })`; results are oldest first.
- **Comment**: `issue_comment({ id, body })`.
- **Apply or remove labels**: `issue_label({ id, add?, remove? })`; this is delta-based.
- **Close**: `issue_close({ id, comment? })`; a closing comment is recorded atomically.

Issue references are tracker IDs or URLs. Bare `#42` and `!67` references do
not resolve through the tools; use the ID or URL present in the reference.

When triaging, every generated comment must start with:

> _This was generated by AI during triage._

`to-spec` and `to-tickets` publish agent-ready Issues directly. They apply the
`ready-for-agent` triage role without sending the Issue through another triage
cycle.

## When a skill says "publish to the issue tracker"

Create an Issue with `issue_create`. Use `wayfinder_chart` or
`wayfinder_create_ticket` for Wayfinder resources.

## When a skill says "fetch the relevant ticket"

Use `issue_read` with its ID or URL. Use `wayfinder_get_map` or
`wayfinder_get_ticket` for Wayfinder resources.

## Wayfinding operations

Wayfinder resources use the dedicated tools:

- **Map**: `wayfinder_chart` creates a map with Destination, Notes,
  Decisions-so-far, Not-yet-specified fog, and Out-of-scope sections.
- **Child Decision ticket**: `wayfinder_create_ticket` creates one child
  Decision ticket with a `research`, `prototype`, `grilling`, or `task` type.
- **Blocking**: `wayfinder_set_blocking` wires dependencies. A ticket is
  unblocked when every ticket blocking it is closed.
- **Frontier**: `wayfinder_list_frontier` lists open, unblocked, unclaimed
  Decision tickets.
- **Claim**: `wayfinder_claim` records the current session's claim before work
  begins. Claiming is the session's first write.
- **Resolve**: `wayfinder_resolve` records the answer as a Resolution comment,
  closes the Decision ticket, appends its title, link, and gist to the map's
  Decisions-so-far, and reports newly unblocked tickets.

The selected tracker owns the underlying persistence and native relationships;
the skill workflow remains the same across backends.
